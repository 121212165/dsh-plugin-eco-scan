## B. 新问题发现（7 条 RETRO.md 未覆盖）

> 以下均为本轮实际踩到/观察到的问题，逐条可独立提 issue；**不重复** RETRO.md 的 7 条（数据入口、字段字典、.gitignore、Windows、onboarding、runbook、velocity）。

### B1. 标签“47 金融/行情”分类精度与召回双低（数据 / 分类质量）

- **现象**：官方 tag47 只有 171 仓；但按 repo 名严格判定（stock/fund/invest/finance/trading/quant/行情/金融/量化… 并排除 sticker/quantum/marketplace 等误匹配）得到 130 个高置信金融仓，其中仅 73 个打了 47，**57 个未打**。两者并集 228 仓，tag47 仅覆盖约 **32%** 的金融需求面。同时 tag47 内部混入 `@better-er/dsh-cache-billing`（LLM 成本）、`zhing99-hash/dsh-dafeiyu-jinrong`（人格/娱乐）、`dawnsss/dsh-clashverge`（网络工具）等非投研仓。
- **影响**：所有按 tag47 统计的需求分析都会系统性漏掉约 2/3 供给；开发者按标签找竞品看不全；金融标签的信号被污染。
- **证据**：未打 47 的高热度金融仓：`zhu1090093659/dsh-trading`（★355）、`hancao97/hanai-investment-dsh`（★126）、`weaxs/stock-analysis-plugin`（★96，wk348）、`fleekelon/dsh-fintax`（wk1,564）、`nickszy/dsh-wealth`（wk967，gr190.4）、`iasiv5/dsh-stock-kanban`（wk2,240，gr574.7）、`perrylink/dsh-fund-research`（★68，wk656）、`tradercjz/dsh-dolphindb`、`xby-skill/xby-vnstock`。
- **建议（issue 标题：为 tag47 建立关键词辅助打标与误分审计）**：用 repo id + README 关键词对 50 标签做二次打标，发布 `tag-audit.csv`（每标签的疑似漏标/误标 top20）；在 `meta` 增加 `tagAliases/keywordRules`；本报告所有数字需标注“基于 tag47 的下界”。

### B2. heat 时序只保留 18 个头部标签，金融/数据库/统计完全缺席（数据 / 趋势盲区）

- **现象**：`meta.heat` 仅 18 条（网页界面、会话管理、智能体、模型接入、工作区、桌面客户端、设计/排版、编码/代码、技能/Prompt、安装/管理、文件/目录、文档/笔记、插件市场、搜索/检索、成本/额度、图像/绘图、MCP、安全）。标签 **47 金融、36 数据库、34 统计/监控、35 导出/归档全部不在其中**，`digest.md` 的 HEAT 章节没有任何垂类。
- **影响**：无法回答“金融需求在升温还是降温”。即使按 RETRO #7 补齐连续快照，heat 的筛选逻辑仍会把垂类挡在门外——这是一个独立于 velocity 的结构性盲区。金融仅有 27 个高信号仓（wkSum 16,948，全场最低），不足以替代时序趋势判断。
- **证据**：`meta.heat.length=18`；47/36/34 的 `some()` 检查均为 false；金融 `wkSum=16,948`（50 标签最低）、高信号仓 27/171。
- **建议（issue 标题：heat 输出保留全部 50 标签或显式声明筛选阈值）**：热榜改为全量输出，或对 cov≥0.5 的标签单独建“垂类 heat”；在 `digest.mjs` 增加 `--heat-all` 开关并在简报中声明“趋势仅代表头部标签”，避免领域报告误用。

### B3. `digest.mjs` 仍用 row[10] 当“主榜”过滤，TOP60 口径错误（工具 / 产物正确性）

- **现象**：`data/digest.mjs:56` 写的是 `ROWS.filter(r=>r[10]===1||r[2]>2000)`，标题却写 `TOP 60 BY SCORE (main rows)`。而 row[10]=1 只有 **174** 仓（= `meta.counts.enriched`），真正主榜 `mainRows=18,829`、`coverage≥0.5=18,462`。该过滤的并集只有 **255 仓**（174 enriched + 81 高 star），仅占真实主榜 1.4%。
- **影响**：`digest.md` 的“TOP60 主榜”实际是“enriched ∪ 高 star 仓”，大量高分但低 star 的新仓（包括本报告里的金融新仓）被错误排除；下游 agent 引用 Top60 判断领域热度时口径失真。RETRO #2 虽已澄清字段映射，但修正只停留在“综合阶段人工校正”，**生成器代码从未修复**。
- **证据**：`col10===1 →174`；`stars>2000 →81`；并集 255；`cov≥0.5 →18,462`；`meta.mainRows →18,829`。
- **建议（issue 标题：修复 digest.mjs 主榜过滤字段并重生成 digest.md）**：改为 `r[11]>=0.5`（coverage）并与 `meta.mainRows` 对齐；在标题标注口径；加单测断言 Top60 全部来自 cov≥0.5 集合。

### B4. 低覆盖“高分空壳”与主榜仓混排，榜单可读性差（评分展示 / 流程）

- **现象**：综合分公式为“四项百分位加权 ÷ coverage”，coverage<0.5 不归一而标“低信号”；但产物里低信号仓与高信号仓同表混排，没有醒目标记。结果：`runweok/dsh-tushare`（age=2，★0，wk=null，cov=0.1）拿到 score=54.8，反而高于有真实数据的 `stockmcp-net/dsh-stockmcp`（cov=1，★1，wk=37，score=37）；金融 171 仓中 81 个 cov<0.5。
- **影响**：用户/Agent 难以区分“真热门”与“刚建仓只有 age 信号”；领域选品时容易被高分空壳误导，尤其在金融这种 83% 无下载数据的垂类里更严重。
- **证据**：上述两个仓库的 score/coverage/star/weekly 对照；金融低覆盖 81/171=47.4%。
- **建议（issue 标题：在主榜与 Top60 中显著标注/降权低信号仓）**：表格增加“信号等级”列（cov≥0.5 / <0.5），低信号仓单独分区或排序时乘惩罚系数；`AGENT_BRIEF` 补充“分数≠质量”的显式提示。

### B5. 数据产物没有“领域”聚合视图，且 rows 无 description 字段（数据 schema / 流程）

- **现象**：`digest.md` 只有 per-tag、family rollup、Top60、matrix、heat、downloads 六种视图，没有“领域维度”（如金融 = tag47 ∪ 相关关键词 ∪ 数据/知识标签）；`rows[]` 的 14 个字段里没有任何 description/README 摘要，领域判定只能靠 repo 名启发式（本报告为此写了 3 个 scratch 脚本，见 `.scratch/`）。
- **影响**：每个领域 agent 都要重复造轮子做领域归并，且因无描述只能猜意图（B1 的误分即源于此）；换人执行时领域口径无法复用，报告之间不可比。
- **证据**：AGENT_BRIEF 行结构 14 字段无 description；`miscNoDesc=1,166`；本轮领域分析新增 3 个一次性脚本，无法沉淀为资产。
- **建议（issue 标题：digest 增加 domain rollup 并在导出中提供 description）**：在 `meta` 预定义领域标签组（金融/开发/设计/媒体…）并输出领域表；`eco-core export` 增补 `description`/`readmeSummary` 列；把领域归并脚本固化为 `data/digest.mjs --domain`。

### B6. 同功能金融插件命名高度重复、生态碎片化且无去重信号（生态 / 流程）

- **现象**：金融 171 仓里存在至少 10 组“仅差作者名”的重复后缀簇：`dsh-stock-ticker`×4（feizhuniu-infja / kfat77 / f1426912008 / lengyeyu123）、`dsh-stock`×4、`dsh-stock-quote`×2、`dsh-stock-watch`×2、`dsh-us-stocks`×2、`dsh-stock-research`×2、`dsh-astock`×2、`dsh-market-radar`×2、`dsh-bookkeeping`×2、`dsh-chat-fold`×2。
