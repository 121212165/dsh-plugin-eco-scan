## A. 领域需求分析

### A1. 需求现状：有"安全"供给，但"合规/政企"几乎空白

**1）安全域体量小、增长弱。** 标签 39「安全」共 **1,848** 仓，仅占全库 38,549 的 **4.8%**；周下载合计 **279,742**，占全库 7,837,245 的 **3.6%**；增长率中位数 **-1.3%**、30 天内新建 **702** 仓——在 50 个标签中属中下游（对比：会话管理 7,884 仓、网页界面 8,678 仓）。安全域有供给，但明显不是生态热点。

**2）关键词需求面广，但"真合规"稀缺。** 仓库名关键词命中量：

|---|---|---|---|---|
| 安全 / security | 675 | 105,364 | -1.7% | 34 |
| 审计 / audit（含 log/trace） | 435 | 35,345 | -1.5% | 16 |
| 权限 / rbac / auth | 448 | 50,175 | -0.5% | 26 |
| 政企 / enterprise / gov | 353 | 41,149 | **-4.7%** | 10 |

其中显式含 `compliance`/`合规` 的仓库仅 **8** 个（7 个无周下载）；含 `governance/治理` 仅 **28** 个且 **93%** 无周下载。**"合规"作为一个可检索的赛道几乎不存在。**

**3）交叉能力位是明显空白。** 安全(39) 与关键能力的交集仓数：

主矩阵同样印证：`工作区×安全=40`，是工作区行所有能力位中倒数第二低（仅高于 路由/网关=28，对比 工作区×网页界面=668）；`技能/Prompt×安全=96`、`会话管理×安全=94`。**"政企工作区 + 安全 + 审计导出"的三位一体组合基本无人做。**

**4）偶发高增长说明需求在被零星验证。** 带周数据的安全仓增长榜：`dsh-stock-kanban` +574.7%（wk 2,240）、`aicivilization/dsh-mishu` +289.8%（wk 1,224）、`drscrewdriver/dsh-session-guard` +222.8%（wk 3,257）、`lawli3tcoding/dsh-approval-review` +105.6%（wk 481）、`hunmer/dsh-team-control` +61.8%（wk 1,655）、`perrylink/dsh-permission-rules` score 95.8 / wk 2,221 / +30.5%。这些是政企场景（审批、团队管控、会话守护、权限规则）的真实需求信号。

### A2. 未满足点（Gap）

- **G1 — 审计闭环缺失。** audit/log/trace 命名仓 104 个但 **86% 无周下载**；同时"安全∩导出归档"仅 52、"安全∩诊断"仅 37。政企要求的"会话可追溯、可导出、可归档成证据链"需自行拼装多个插件，无一体化方案。
- **G2 — 合规语义检索缺失。** 50 个标签中只有单一「安全」(39)，没有「合规/GDPR/等保/SOC2/审计/权限/隐私」子标签；183 个合规命名仓无专属标签可检索，采购方无法按合规框架筛选。
- **G3 — 私有化 / 本地化合规模板缺失。** 政企命名仓 353 个增长中位数 **-4.7%**（仅 10 个正增长），全库 segments 中也没有 compliance/audit 赛道（segments 仅 framework-runtime 13,280 / ui-client 4,877 / tools-devx 4,176 / other 9,377 / search-knowledge 1,492 / memory-context 1,924 / archive-export 1,364 / cost-budget 1,329 / telemetry-analytics 730）。本地部署 + 中文 + 等保的合规包无人提供。
- **G4 — 供给可验证性缺失。** 安全标签 1,848 仓中 **1,470（79.5%）无周下载**、**1,551（83.9%）无增长率**、**1,093（59.1%）star=0**；两款最高星 `dsh-purge`（★8,813）与 `mmparko/dsh-purge`（★5,077）周下载均为 null。高星不等于可用，采购方难以判断。
- **G5 — 供应链安全空白。** 443 个 `*-guard` 命名仓里绝大多数是 loop/cookie/price 之类运行守护；真正面向"插件/技能安装前审查"的只有零星几个（`pensivefei/dsh-secure-audit` score 85.8 / wk 982、`shanhaifish/dsh-plugin-security-review` +77.8%、`bruc3van/safer-dsh-market` wk 822），且 安全∩诊断 仅 37 仓。

### A3. 推荐开发插件（≥5 条，带数字证据）

1. **会话审计归档插件（Audit-Trail Exporter）** — 一键把会话 + 工作区变更导出为可验证审计包（含时间戳、操作者、哈希）。命中 39+35+21+22。证据：安全∩会话=215、安全∩导出=52、安全∩工作区=74；audit 命名 104 仓 86% 无周下载。目标：政企 IT、合规审计员。**优先级高／难度中。**

3. **RBAC 权限与审批门禁插件** — 工作区内按角色控制工具/会话操作，关键动作走审批流。命中 39+21+22+43 生产力。证据：权限命名 448 仓（87% 无周下载）；`dsh-permission-rules` score 95.8 / wk 2,221 / +30.5%、`dsh-approval-review` +105.6%、`mrweicodes/dsh-permgate` +66.9%、`dsh-team-control` +61.8%。目标：企业中台、团队协作管理员。**优先级高／难度中。**
4. **插件 / 技能供应链安全审查** — 安装前静态扫描技能与插件（密钥、外联、越权），输出风险分与白名单。命中 39+41 安装管理+40 插件市场+46 诊断。证据：安全∩安装管理=164、安全∩诊断仅 37；`dsh-secure-audit` wk 982、`dsh-plugin-security-review` +77.8%；443 个 guard 仓无统一审查标准。目标：政企安全团队、市场运营方。**优先级中高／难度中。**
5. **凭据 / Cookie 生命周期治理** — 统一收纳、轮转、脱敏存储登录态与密钥，支持一键清理。命中 39+21+24 Shell。证据：secret/credential 命名 **421** 仓（81% 无周下载）、cookie-guard 撞名 8 个、`dsh-auth-cookie-guard` score 87.6 / wk 1,699、`dsh-credentials-keyring`、`dsh-git-credentials` wk 420。目标：安全运维、 DevOps。**优先级中／难度低-中。**
6. **政企本地化合规基线包（中文 + 等保模板）** — 本地部署自检、日志留存策略、等保/SOC2 证据清单模板。命中 39+38 中文本地化+22 工作区+45 框架。证据：政企命名 353 仓增长中位数 -4.7%、合规命名 183 仓 -2.3%、governance 28 仓 93% 无周下载；`lan-tina-ws/dsh-windows-shell-policy`、`ddtcorex/govard` 为零星探索。目标：政企/国企信息化部门、SI 集成商。**优先级中／难度中。**

## B. 新问题 / 摩擦点发现（ RETRO 7 条之外 ）

> 以下均**不重复** RETRO.md 已列的 7 条（数据入口/字段字典/.gitignore/Windows/agent onboarding/runbook/velocity 单快照）。每条按 现象 + 影响 + 证据 + 建议 给出，可直接提 issue。

### B1【工具·分类法】单一「安全」标签吞掉全部合规子域，无法按合规框架检索
- **现象**：50 标签体系里只有 `id=39 安全` 一个安全类标签，把 loop-guard、cookie-guard、PII 脱敏、审批门禁、供应链审查全塞进同一桶；`meta.lanes` 虽有 39 安全 lane，但**没有"合规/审计/政企"lane或 segment**（segments 9 个均无合规类）。
- **影响**：合规采购方无法按 GDPR / 等保 / SOC2 / RBAC 筛选；扫描器无法量化合规供给；本报告也只能靠仓库名正则近似还原需求，结论有偏差。
- **证据**：安全标签 1,848 仓；合规命名 183 仓、显式 compliance 8 仓、governance 28 仓，这些全部无专属标签可过滤；443 个 `*-guard` 仓混在同一标签。
- **建议**：新增 4 个 facet 子标签 `安全-审计取证 / 安全-隐私脱敏 / 安全-权限审批 / 安全-供应链`，或对 39 安全做二级 `subclass` 字段；`meta.segments` 增 `compliance-governance` 赛道；`lane` 增 audit/compliance。可提 issue：「tags 分类法缺少合规/审计细分维度」。

### B2【数据·指标稀疏】安全合规域 repo 级指标缺失率远高于全局，高结论不可验证
- **现象**：安全标签仓库的 `weekly`（周下载）/`growth`/`stars` 大面积缺失，且不是单快照问题（区别于 RETRO #7 的 velocity）。
- **影响**：增长率、热度、star 排名在合规域全部失真；两款最高星 purge 插件无周下载，无法判断真实使用；榜单/推荐会把 null 当 0 惩罚或反向虚高。
- **证据**：安全(39) 1,848 仓中 `weekly=null` **1,470（79.5%）**、`growth=null` **1,551（83.9%）**、`stars=0` **1,093（59.1%）**；coverage=0.1 占 **936（50.6%）**；合规命名 183 仓中 157（86%）无 wk、101（55%）cov=0.1；`kingcharleslzy-ai/dsh-purge` ★8,813 / wk=null、`mmparko/dsh-purge` ★5,077 / wk=null。全局 weekly=null 约 31,548/38,549（82%），但安全域高星仓同样缺数据，尤其致命。
- **建议**：对 `weekly=null` 的高 star 仓补 npm registry 二次抓取并在 meta 标注 `metricSource`；报告对 `weekly=null && stars>1000` 的仓统一打「不可验证」标记。可提 issue：「安全/合规类高分仓周下载缺失率达 79.5%，需补采或显式降权」。

### B3【工具·发现体验】政企/安全仓严重撞名与同质化，用户无法辨别与选择
- **现象**：大量仓库使用完全相同的 basename（不同 owner），且 `*-guard` 高度同质化。
- **影响**：采购方/开发者搜到 24 个 `dsh-purge` 无法分辨官方与可信版本；同名插件质量参差，劣币驱逐良币，也污染本报告按名称去重的统计。
- **证据**：`dsh-purge` ×24、`dsh-plugin-guard` ×14、`dsh-loop-guard` ×9、`dsh-cookie-guard` ×8、`dsh-guard` ×8、`dsh-guardian` ×7、`dsh-plugin-audit` ×5、`dsh-auth` ×4；全语料 `guard` 命名 443 仓、`purge` 命名 83 仓。
- **建议**：市场/扫描输出按 basename 聚类去重并展示 owner 与验证徽章；新增 `name_collision` 指标，榜单对同名组只展示 star/下载最高者。可提 issue：「repo basename 撞名聚类：dsh-purge×24 等，需去重与可信度标记」。

### B4【数据·主题污染】关键词/标签误判夸大合规供给，统计可信度受影响
- **现象**：用关键词做领域统计时，`audit` 正则命中 `dsh-todo-time-log`（时间日志）、`dsh-logistics`（物流）、`dsh-login`（登录），并非审计；`安全` 标签里混着 `dsh-peakpriceguard`（价格守护）等与合规无关的插件；`purge` 仓多被打成「安全+导出」但实为上下文清理。
- **影响**：任何"合规插件有多少"的数字都会被污染；供应链/审计类供给被高估，误导开发决策与榜单。
- **证据**：审计关键词 435 仓中混入 log/login/logistics 类；`iasiv5/dsh-stock-kanban` 增长榜第一（+574.7%）却带「安全」标签，实为股票看板；`nowscott/dshpeakpriceguard` 带「安全」标签实为价格守护。
- **建议**：分类增加描述语义二次校验（当前 rows[] 无描述字段，仅靠名+标签）；维护「合规关键词白/黑名单」并让 digest 输出「疑似误分类」计数；报告引用时标注该局限。可提 issue：「tag/keyword 主题污染：价格守护/股票看板被打上安全标签」。

### B5【流程·赛道空白】合规/政企赛道没有白名单与需求验证机制，增长为负却无人唤醒
- **现象**：扫描器产出了 lanes（26 条，含安全）与 segments（9 条），但没有任何合规/审计/政企专属赛道或落地案例库；政企与合规命名仓增长中位数为负（分别 -4.7% / -2.3%）。
- **影响**：合规需求信号微弱且分散，开发者看不到明确赛道，形成"没人做→需求不被验证→更没人做"的循环；本报告只能靠主观判断优先级，缺少赛道级 KPI 支撑。
- **证据**：政企命名 353 仓、正增长仅 10；合规命名 183 仓、正增长仅 6；显式 compliance 仅 8 仓；governance 28 仓 93% 无 wk。对比全库 90 天内新建 15,963、主榜 18,829——合规域既小又冷。
- **建议**：在扫描器增加 `compliance` 赛道与「政企合规白名单仓库」清单；下一版对这批仓库做连续快照跟踪，设「正增长仓数 / 有 wk 仓数」作为赛道健康度 KPI。可提 issue：「新增 compliance-governance 赛道与政企仓库白名单，跟踪需求信号」。

### B6【工具·触达失衡】安全合规插件几乎不进入下载/触达主渠道，需求与分发脱节
- **现象**：全库下载 Top30 里没有一款纯合规/审计插件；最高可见的安全相关仓 `kenryu42/cc-safety-net`（wk 49,920）本质是命令行 Git 安全网而非合规工具；真正合规插件（`dsh-secure-audit` wk 982、`dsh-audit-bundle` wk=null）触达极低。
- **影响**：即使开发出合规插件，也缺乏被用户发现的渠道（reachCoverage 全库仅 18.16%、主榜 37.02%）；供给与需求双低，产品难以起量。
- **证据**：downloadTop 前 30 仓库名无一含 compliance/audit/gov/privacy；安全域周下载合计 279,742，仅占全库 7,837,245 的 3.6%；`dsh-audit-bundle`、`dsh-policy-drift-proof` 等 wk=null。
- **建议**：市场设「合规/安全」分区与编辑精选位；对合规插件给流量加权或新物种扶持标签；扫描器输出 `complianceReachPct` 单独监控该域触达。可提 issue：「合规插件触达缺失：downloadTop30 零合规仓，需分区分发」。
