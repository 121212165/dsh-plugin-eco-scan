# A8 研究报告：模型 + 数据族插件生态需求分析

> 研究员：A8｜分工：模型族（31 模型接入 / 32 路由网关 / 33 成本额度）+ 数据族（34 统计监控 / 35 导出归档 / 36 数据库 / 47 金融行情）
> 数据源：`eco-data.json`（快照 2026-11-16，38,549 仓）+ `digest.md`；统计口径为含该标签的全部仓库（含低信号仓），结合主榜 Top 榜验证。

## 0. 结论速览（TL;DR）

1. **需求侧极热、供给侧偏冷的结构性错配**：模型族 7,449 仓（周下载合计 1,284,115），数据族仅 3,021 仓（周下载合计 443,166）——数据族仓库数只有模型族的 **40.6%**，周下载只有 **34.5%**；而交互族高达 18,522 仓。**“数据”是整条生态最薄的环节**。
2. **数据库（36）与金融/行情（47）是最明显的两处供给空白**：数据库 227 仓（倒数第 4）、金融 171 仓（全表最小），两者 `score>=90` 均为 **0**，`maxScore` 分别仅 88.8 / 84.2。
3. **成本/额度是“单品爆款 + 山寨泛滥 + 整体负增长”的畸形赛道**：2,152 仓但增长中位数 **-1.4%**（全表最差一档）；`dsh-cost-meter` 同名仓 17 个，其中只有 1 个 `score>=70`、4 个有周下载；榜首由 `ebony-vinyl/dsh-our-free-model`（98.4）与 `t-auto/dsh-ops`（98.4）这两个跨标签“免费模型/运维”主题占据。
4. **模型接入是大赛道但“高质量稀疏”**：5,420 仓中仅 1,183 仓（21.8%）有周下载，2,678 仓（49.4%）有 star，`score>=90` 仅 38 仓；真正带 sun 的头部高度集中在“免费额度”叙事。
5. **路由/网关缺“可信赖的通用件”**：1,191 仓中 `score>=90` 仅 9 仓、`★>=100` 仅 9 仓；`alice-marx/dsh-model-router` 周下载 4,686 但增长 **-70.1%**，说明现有路由插件生命周期短、用户留存差。

## 2. 分标签深度分析

### 2.1 模型接入（31）：大赛道，但热度=「免费额度」而非「能力接入」

- 规模第 4（5,420 仓），30 天新建 1,991（36.3%），说明仍是新增最活跃的赛道之一。
- **但信号质量低**：仅 21.8%（1,183/5,420）有周下载，`score>=90` 仅 38 仓，star 中位数 0、star 总和 202,918（对比智能体族 1,041,696）。
- Top by score：`fourzkw/dsh-drawai`（98.7 / ★667 / wk 7,817 / 增长 **+92.4%**）、`ebony-vinyl/dsh-our-free-model`（98.4 / ★76,025 / wk 20,708 / +25.7%，age 仅 52 天）、`xdtrees/dsh-xdpool`（97.7，标签含自动化+模型+路由+成本）。
- Top by weekly 更说明问题：`dddmuc/dsh-free-search`（39,301）、`han-1413141/dsh-cost-meter`（38,681）、`dingminhua/dsh-connect-workbuddy`（34,342）——**下载榜前 3 有两个是“免费/额度”工具，而非模型能力本身**。
- 机会点：专门做 **Ollama / HuggingFace / OpenAI 兼容的统一接入层 + API Key 轮换**（`goodandready/dsh-key-rotation` wk 1,927、`firefox2100/dsh-ai-providers` wk 1,775 且 +64.2% 已验证需求），避开“免费.model”红海。

### 2.2 路由/网关（32）：1191 仓却无一“高分精品”，生命周期短

- 1,191 仓，`score>=90` 仅 9、`★>=100` 仅 9，周下载合计 171,911（仅模型接入的 17.8%）。
- 头名 `xdtrees/dsh-xdpool`（97.7 / wk 4,734 / +34.6%）、`dingminhua/dsh-connect-qoder`（95.6 / wk 5,046 / +17.4%）——共性都是「模型接入 + 路由 + 成本」三合一。
- `alice-marx/dsh-model-router` 周下载 4,686 却 **-70.1%**；`regrevia/dsh-fast-mode` -58.9%；同名 `dsh-model-router` 16 个克隆中只有 1 个 `score>=70`——**跟风多、沉淀少**。
- 交叉空白（来自 meta.matrix）：`工作区 ∩ 路由/网关 = 28`、`技能/Prompt ∩ 路由/网关 = 51`，而 `模型接入 ∩ 路由/网关 = 332`——路由插件几乎全部堆在“模型层”，**缺面向工作区/技能编排的路由**。

### 2.3 成本/额度（33）：爆款与山寨并存，整体在收缩

- 2,152 仓，增长中位数 **-1.4%**（本族最差），`new30=848`（39.2%）：大量新仓涌入但大盘在缩。
- 榜单被两个 98.4 分仓统治：`ebony-vinyl/dsh-our-free-model`（★76,025 / wk 20,708 / +25.7%）、`t-auto/dsh-ops`（★5,850 / wk **73,476** / +26.9%）。
- `han-1413141/dsh-cost-meter`：wk **38,681**、score 86.9、增长 -2.5%——**需求确凿但已进入平台期**。
- 克隆化严重：全库 `dsh-cost-meter` 17 个（仅 1 个 score≥70、4 个有下载）、`dsh-our-free-model` 7 个（1 个高分）、`dsh-ops` 16 个（1 个高分）。
- **真正的空白是“预算/限额/预警”而非“看余额”**：`成本/额度 ∩ 安装/管理 = 67`、`成本/额度 ∩ 通知/提醒 = 31`（相对 2,152 仓极小）；`成本/额度 ∩ 模型接入 = 693` 说明成本插件几乎都黏在模型层，缺少跨会话、跨工作区的统一预算治理。

### 2.4 统计/监控（34）：头部缺席，token 统计是小散乱

- 1,816 仓，但 `score>=90` 仅 3、`score>=80` 仅 14，最高分由跨标签的 `ebony-vinyl/dsh-our-free-model` 与 `t-auto/dsh-ops` 占据——**真正专注统计的头部很弱**。
- 专注统计的高分仓量级都很小：`better-er/dsh-live-token-stats`（89.6 / wk 1,127 / **+113.9%**）、`licyer/dsh-token-monitor`（87.2 / wk 806）、`moonlitdropofblood/dsh-token-stats`（84.5 / wk 955）。主题几乎全是“token 用量”。
- `统计/监控 ∩ 网页界面 = 497`（说明用户想要看板），但 `统计/监控 ∩ MCP = 39`、`∩ 智能体 = 185`——**缺跨 Provider 统一账单 + 可视化 + 阈值告警的成品**。
- 热度（26 周）末值 192、峰值 374，仍是活跃赛道，不是衰退赛道。

### 2.5 导出/归档（35）：有下载无精品，增长靠短期爆发

- 898 仓，`score>=90` 仅 3，周下载合计 138,018。
- `michengai/dsh-archive-manager` wk **27,252** 但 score 仅 80.5、增长 **-28.4%**——下载高、口碑低，是典型的“将就着用”。
- 高分仓 `hkkz9522/dsh-session-manager`（96.4 / wk 3,741 / +24.9%）、`lire1131/dsh-undo-savepoint`（94 / wk 2,156）。
- 爆发型新仓：`boe1900/dsh-ppt` 增长 **+1048.9%**、`summerscar/dsh-plugins` +479.6%，但 age 仅 59/7 天、star 0-1——**需求真实但极不稳定**。
- `导出/归档 ∩ 会话管理 = 371`，说明主要场景是会话存档；缺结构化（JSON/Markdown/CSV）导出 + 可检索归档。

### 2.6 数据库（36）：倒数第 4 的供给洼地，无一款高分产品

- **仅 227 仓**（全表倒数第 4），周下载合计 39,779，`score>=90 = 0`、`>=80` 仅 3、`maxScore = 88.8`。
- 榜首 `anweat/dsh-web-search-pro`（88.8 / ★88 / wk 1,541）本质是“搜索 + 数据库”而非数据库管理；`dream-num/univer-workspace`（74.8 / ★2,286 / wk=null）是文档工作区顺带挂数据库标签。
- 真正做 DB 的仓都是小体量：`mr-mihu/dsh-dbhub-live`（79.5 / wk 923 / **+196.8%**）、`halcyon6669/dsh-db-mcp`（77.2 / wk 3,442 / **+138.9%**，age 仅 8 天）、`stardustlc666/dsh-sql`（70.9 / wk 970）、`blkpne/dsh-database`（76.5 / wk 731）。高增长 + 低基数 = **需求正在启动但无人占位**。
- 交叉极度稀疏：`数据库 ∩ 模型接入 = 16`、`数据库 ∩ MCP = 11`、`数据库 ∩ 智能体 = 55`、`数据库 ∩ 会话 = 40`——数据库几乎是生态孤岛。
- 同名 `dsh-db` 仅 12 个克隆（3 个 score≥70）——连山寨都没形成，说明不是红海而是**真空**。

### 2.7 金融/行情（47）：最小赛道，全是短命单点

- **仅 171 仓（全表最小）**，周下载合计 **16,948**、star 合计 **817**、`★>=100` 仅 1 仓（`minara-ai/minara-skills` ★377 但 wk=null）、`score>=90 = 0`、`maxScore = 84.2`。
- 榜首 `suifei/dsh-market-lens`（84.2 / ★5 / wk 4,405 / age 仅 **10 天**）；其后 `mengmenghao/dsh-stock-quote`（71.5 / wk 1,213 / age 11 天）、`fanxingchunshui/dsh-stock`（71.4 / wk 1,143 / age 9 天）——**头部几乎都是一周内新仓，0-1 star，无沉淀**。
- 主题局限于单点行情：雪球（`wanderer-yk/dsh-xueqiu`）、同花顺持仓（`pm25000/dsh-ths-holdings`）、量化（`pengpengyi92/dsh-quant`）、Trading212（`kevoyuan/dsh-trading212`）。
- `金融/行情 ∩ 插件市场 = 33`、`∩ MCP = 15`、`∩ 智能体 = 30`——**没有“行情 MCP + 投研编排”的成套产品**。

## 3. 横向洞察：为什么该做「数据族」插件

1. **矩阵 0 格/低格就是机会**：`工作区 ∩ 路由/网关 = 28`、`技能/Prompt ∩ 成本/额度 = 43`、`数据库 ∩ MCP = 11`、`金融 ∩ MCP = 15`。这些格子数字极小，说明把“数据能力”接进编排/工作区几乎是空白。
2. **头部被跨标签爆款垄断**：33/34 两族的最高分仓都是 `ebony-vinyl/dsh-our-free-model`(98.4) 和 `t-auto/dsh-ops`(98.4)，且两者都带“成本 + 统计”——证明用户真正买单的是**“省成本 + 看得见用量”的组合**，而不是单一功能。
3. **克隆率 = 需求验证器，也是机会窗口**：成本/模型/路由三个热门主题各有 16-17 个同名克隆，但高分率仅 1/16~1/17；**用户想要但没人做扎实**。数据库/金融连克隆都没有（dsh-db 12 个、金融无成规模克隆），是尚未被发现的蓝海。

### 优先级排序依据

- **高优先级**=需求已被真实下载验证（榜首 wk 38,681 / 4,405 / 高增长）**且**供给质量明显不足（score≥90 ≤ 9 或 clone 高分率 1/17）。
- **中优先级**=需求存在但当前集中在新仓爆发或孤岛状态（数据库/金融/导出），需承担市场教育成本。

> 数据局限：`velocity` 无连续快照（仅单日），growth 为存量估算；低信号仓（coverage<0.5，全库 19,868 仓）大量 `weekly=null`，周下载合计仅覆盖 7,001 仓。结论以“标签计数 + 头部仓实例 + 交叉矩阵低格”三类证据交叉验证。
