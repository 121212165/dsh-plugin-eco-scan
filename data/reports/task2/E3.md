# 企业未满足需求分析 E3 — 企业流程编排与协作

> 研究员：E3｜分工主题：**企业流程编排与协作未满足需求**
> 数据源：`eco-data.json`（快照 2026-11-16，38,549 仓、50 标签、周下载总和 7,837,245）＋ `digest.md` ＋ 任务一综合报告。
> 方法：矩阵格 `n` 与占比采用 `meta.matrix`（父标签归属口径，`parentTotal` 为分母）；标签直交计数用 `rows[].tags` 二次统计复核；周下载=装机代理，增长率=单快照动能信号，30 天内新建=供给拥挤度。单快照、`velocity` overlap=0，结论以结构性空白为主，不把增长率当严格时序。

---

## 1. 执行摘要

**核心判断：企业要的是"可管控、可审计、可复用、团队协同"的编排底座，而生态供给的是"个人玩具级"的编排小工具。两者之间存在系统性错位。**

六个最硬的数字证据：

1. **泛工作流是"伪热"**：工作流标签 1,418 仓、周下载合计仅 **172,156**（占全库 2.20%）、增长中位 **-0.7%**；其中 **1,136 仓（80.1%）无周下载**、**981 仓（69.2%）star≤1**、主榜仅 **6 仓（0.4%）**，却有 **505 仓（35.6%）30 天内新建**——低质供给涌入、无高质量沉淀。
2. **场景化审批流却有真实落地**：`bushizhanghan/dsh-publish-gate` 周下载 **12,011 / +71.9%**（Git+编码+安全+市场），`9087/dsh-diff-approval` 周下载 **2,592**，`cuddly-guacamole/dsh-auto-approval-llm` **+38.5%**，`fzqxdedafeiyu/dsh-approval-reason-dock` **+246.7%**，`lawli3tcoding/dsh-approval-review` **+105.6%**，跨会话审批 `zsjs110110-cpu/dsh-cross-session-approval` 周下载 **594**。说明"审批点"是真需求，但都是各自为战的孤立小插件。
3. **编排×管控近乎空白**：工作流×统计/监控仅 **23 仓（1.6%）**、工作流×成本/额度仅 **27 仓（1.9%）**，均 <3%；矩阵中智能体×统计 **112（2.99%）**、智能体×成本 **98（2.62%）**、技能×统计 **42（2.53%）**、技能×成本 **43（2.59%）**；编排族 9,514 仓中带统计或成本标签者仅 **495 仓（5.2%）**，且上述六组交集**主榜仓库数全部为 0**——没有任何一个"高质量编排治理插件"存在。
4. **工作区治理三格全空**：工作区×框架/运行时 **43（2.06%）**、工作区×记忆 **56（2.68%）**、工作区×安全 **40（1.92%，全矩阵最低）**、工作区×统计 **94（4.51%）**、工作区×工作流 **67（3.21%）**。工作区有页面、有会话，却没有版本、审计与回滚能力。
5. **技能版本管理与复用是"零供给"**：技能×Git 矩阵格 **58（3.49%）**（直交 108）；`skills-manager` 关键词 20 仓合计周下载 39,223，其中 **94.9% 集中在 `michengai/dsh-skills-manager` 一仓（37,213，增长 -26.7%）**，其余 19 家合计仅 ~2,010；`skill-registry` / `skill-version` / `skill-share` / `skill-vault` 关键词命中 **0 仓**，`skill-sync` 1 仓但周下载 0。企业要的技能版本锁定、变更审计、团队共享复用完全无人做。
6. **团队协同有需求、无标准**：`nanmicoder/dsh-agent-teams` 周下载 **14,493**（★2,959）、`suifei/dsh-ai-team` 周下载 **32,083（仓龄 6 天）**、`hunmer/dsh-team-control` **+61.8%**（网页+智能体+工作流+安全）、`cq-guojia/dsh-task-ledger` 周下载 **4,965**、`dsh-task-dispatch-table` **+168.8%**、`topmindspace/dsh-super-kanban` 综合分 **96.7 / +82.3%**；但 14 个 `agent-teams` 仿品中多数周下载为 null，看板/台账类仓库 star 中位数低、同质化严重——**需求真实存在，缺的是企业级事实标准**。

## 2. 六大细分需求逐项分析

### 2.1 多智能体任务编排与管控

**需求信号**：智能体标签 6,389 仓 / 周下载 1,133,314，是编排族最大赛道；但智能体×工作流 349（9.33%）远高于智能体×统计 112（2.99%）与智能体×成本 98（2.62%）。即"能编排"很多，"能管控编排"极少。直交复核：`agent&analytics` 185 仓、`agent&cost` 168 仓，合计周下载仅 18,389 / 25,245，且**主榜 0 仓**。

**真实落地样本**（证明是需求而非伪需求）：
- `hunmer/dsh-team-control`：综合分 93.5、周下载 1,655、**+61.8%**，标签 [网页界面, 智能体, 工作流, 安全]——把"团队 + 编排 + 安全"三件事做在一起，恰好命中企业诉求。
- `loyalchiiina/dsh-agent-team-auto-orchestrator`：周下载 1,364、**+403.3%**（仓龄 8 天），标签 [会话, 自动化, 智能体, 工作流]。
- `mario841859784/dsh-expert-orchestrator`：综合分 90.8、周下载 1,482；`contexera/dsh-agent-team`：90.4 分、1,238；`godv61/dsh-task-engine`：89.1 分、1,159，标签含 [Git, 工作流, 技能]。

**空白**：编排产物"跑到哪一步、花了多少、谁批准的、失败如何重试/回滚"全链路可观测与管控层不存在。`dsh-agent-compare`（周下载 92,759、+951.5%）火爆只会"对比"，不会"管控"。

**企业场景**：多智能体流水线的任务分派、并发限额、失败重放、SLA 看板、按部门/项目成本归集。

**建议方向**：企业编排控制台（Orchestration Control Plane）——任务 DAG 可视化 + 状态机 + 执行审计日志 + 并发/配额策略 + 失败重试与补偿，命中标签 **28+29+34+33**，把编排从"能跑"升级为"敢用"。

### 2.2 审批 / 确认流

**需求信号**：`approval` 关键词 118 仓、周下载合计 12,637，但**仅 21 仓有增长数据、9 仓正增长**；`confirm` 关键词 **8 仓、周下载合计 0、增长数据 0**；`gate` 关键词 243 仓中大量是模型网关/鉴权（如 `clarklevis1995/dsh-plugin-mobile-gateway`），真正"工作流审批门禁"极少。

**场景化落地样本**（正增长、有真实装机）：
- `bushizhanghan/dsh-publish-gate`：周下载 **12,011 / +71.9%**，标签 [Git, 编码, 安全, 插件市场]——发布门禁，直接对应企业 CI/CD 审批。
- `fzqxdedafeiyu/dsh-approval-reason-dock`：**+246.7%**、周下载 1,158；`lawli3tcoding/dsh-approval-review`：**+105.6%**、481；`cuddly-guacamole/dsh-auto-approval-llm`：**+38.5%**、720；`mrweicodes/dsh-permgate`：综合分 91.5、1,108 / +66.9%；`zsjs110110-cpu/dsh-cross-session-approval`：594，标签 [MCP, 会话, 智能体, 工作流]——跨会话审批是企业刚需。
- `9087/dsh-diff-approval`：周下载 2,592、综合分 84.9——代码 diff 审批。

**空白**：全是**单点、单动作**审批（一个确认弹窗/一个 diff 审批），没有"多级审批链 + 条件路由 + 委托代理 + 审批留痕 + 超时升级 + 与工作区/会话绑定"的成套方案。确认流（confirm）更是 0 装机。

**企业场景**：代码发布审批、工具调用授权、敏感操作二次确认、费用/额度超支审批、跨部门会签。

**建议方向**：ApprovalFlow 企业审批编排插件——规则化审批链（多人/多级/或签/会签）、审批上下文快照（哪个会话、哪个工作区、哪个 diff）、审计留痕与导出，命中标签 **29+39+21+22+42**。

### 2.3 工作流模板

**需求信号**：`template` 关键词 34 仓，**周下载合计仅 157**；有增长数据的仅 1 仓且为 0/负（`omdsh-dev/plugin-template` 等主要是"插件开发模板"、"Prompt 模板"，如 `nelsonlongxiang/dsh-prompt-templates`）。工作流标签内 `op7418/dsh-guizang-design`（周下载 9,039，综合分 96.7）本质是排版设计流，`q253595422/dsh-imagegen-video` 是生图视频流——都是**消费内容型流程**，不是企业业务流程。

**空白**：没有"可复用业务流程模板库"（如"日报周报生成+评审"、"需求→开发→测试→发布"、"客户工单分级处理"），也没有模板版本、参数化、继承与共享机制。`workflow` 关键词 91 仓周下载合计仅 5,310，有增长数据仅 10 仓。

**企业场景**：新团队快速上手标准流程、跨团队流程复用与统一、审计合规的流程基线。

**建议方向**：WorkflowTemplateHub——模板市场 + 参数化实例化 + 模板版本与变更 Diff + 团队继承/共享，命中标签 **29+30+40+25**；与 2.6 的技能版本治理共用"版本+审计"内核。

### 2.4 会话 / 工作区版本管理与回滚

**需求信号**：
- 工作区 × Git/提交矩阵格 **152（7.29%）**是工作区跨域最高格，说明"工作区里做版本"有需求；但工作区 × 框架/运行时仅 **43（2.06%）**、× 记忆仅 **56（2.68%）**——**工作区没有可回滚的状态内核**。
- `rollback` 关键词仅 **12 仓**，最高 `domitor-syh/dsh-rollback` 周下载 **645**（标签 [会话, 安装管理]）；其余如 `sharedcare/dsh-conversation-rollback`、`antlordgit/dsh-plugin-session-rollback`、`po-et/dsh-session-snapshot` 全部周下载为 null。
- `version` 关键词 18 仓：`acgnnsj/dsh-plugin-versions` 周下载 1,610 / +50.9%、`tangyixiao/dsh-version-manager` 1,182、`yangdongzhen590/dsh-knj-version-control` 标签含 [工作区, Git, 文件, 管理]——但都只是"插件版本展示/更新提醒"，不是工作区状态版本。
- `snapshot` 关键词 16 仓，`uesccda/dsh-plugin-snapshot` 周下载 553 / +72.3%，其余多为临时快照清理/内存快照，无团队级共享快照。
- `confirm` 8 仓周下载 0、`template` 34 仓周下载 157——配套能力同样空。

**空白**：会话/工作区的"检查点 → 变更记录 → Diff → 一键回滚 → 审计"闭环不存在。企业担心的是"智能体改坏了项目/改错了配置，无法回到上一个可信状态"。

**企业场景**：智能体批量改代码后的回滚、配置变更审计、会话状态复现（复现 bug/复盘）、多分支工作流实验。

**建议方向**：WorkspaceCheckpoint——工作区/会话状态快照 + Git 式提交 Diff + 回滚 + 变更审计，命中标签 **22+21+25+39**，与任务一推荐的 WorkspaceGuard 共享沙箱与 ACL 内核，但补齐"可回滚"这一半。

### 2.5 团队任务台账

**需求信号**：生产力/办公标签 805 仓 / 周下载 81,793，其中生产力×智能体直交 149 仓（主榜 20 仓）。团队任务类有明确装机：
- `cq-guojia/dsh-task-ledger`（任务台账）：综合分 89.1、周下载 **4,965**，仅单标签 [生产力/办公]；
- `cq-guojia/dsh-task-dispatch-table`（任务派发表）：周下载 2,118、**+168.8%**；
- `topmindspace/dsh-super-kanban`：综合分 **96.7**、周下载 2,311、**+82.3%**，标签 [会话, 工作区, 设计, 安装管理]；
- `cloader/dsh-taskboard`（主榜）周下载 1,972 但 **-20.7%**、`kira905/dsh-task-board-local`（主榜）788 / +71.7%、`senguk520/dsh-multitask` 周下载 1,611 / +31.1%；
- 多智能体团队：`nanmicoder/dsh-agent-teams` 周下载 **14,493**（★2,959）、`suifei/dsh-ai-team` **32,083**（仓龄 6 天）、`bloodarea/dsh-agent-team-presets` +46.3%；`standup` 关键词 **0 仓**、`scrum` **1 仓且周下载 0**。

**空白**：台账/看板只是"展示层"，**不与智能体任务编排联动**（任务分派→执行状态→审批→工时/成本→审计的闭环缺失）；14 个 `agent-teams` 仿品中多数周下载为 null，说明缺少企业级事实标准。`board` 关键词 276 仓、`kanban` 36 仓，大量低质同质仓。

**企业场景**：迭代看板、跨团队任务分派与跟踪、AI 智能体作为"团队成员"的工时/产出统计、晨会/站会自动化（standup 0 仓即空白）。

**建议方向**：TeamTaskLedger——任务台账 × 智能体执行状态 × 审批 × 成本的一体化看板，命中标签 **43+28+29+34**；把 `dsh-task-ledger` 的需求与 `dsh-agent-teams` 的装机合并到同一管控面。

### 2.6 技能版本管理与复用

**需求信号**：技能/Prompt 标签 3,232 仓 / 周下载 387,424，但技能×Git 矩阵格仅 **58（3.49%，直交 108）**、×统计 **42（2.53%）**、×成本 **43（2.59%）**——技能生态"能装能用，但不能管版本、不能审计成本"。

**关键证据**：
- `skills-manager` 关键词 20 仓合计周下载 39,223，**94.9% 集中于 `michengai/dsh-skills-manager`（37,213，增长 -26.7%）**；其余 19 家合计仅约 2,010（`aa2246740/dsh-skillhub` 935、`pn1024/dsh-skill-market` 1,122、`alone-tree/dsh-skill-mcp-manager` 690…）。`iflytek/skillhub` 有 ★5,429 但周下载仅 621、-3%。
- **零供给关键词**：`skill-registry` 0 仓、`skill-version` 0 仓、`skill-share` 0 仓、`skill-vault` 0 仓、`skill-sync` 1 仓（周下载 0）、`skill-library` 2 仓（周下载 0）。
- 增长为负：`michengai/dsh-skills-manager` -26.7%、`cheshireez/dsh-skill-hub` -10.1%、`cocofhu/skillhub` -13.6% — 现有管理器正在流失用户。

**空白**：技能没有"版本锁定 / 变更 Diff / 回滚 / 审批发布 / 团队私有仓库 / 复用统计"。企业不敢在全团队推广未经审计的技能更新。

**企业场景**：团队内部技能库、技能变更评审、灰度发布与回滚、技能使用与成本分析、依赖锁定（防止上游更新破坏流程）。

**建议方向**：SkillRegistry——技能版本管理 + Git 化变更审计 + 团队私有仓库 + 复用/成本统计，命中标签 **30+25+39+34**；与任务一的 SkillGate（审批）和本报告 2.3 的模板版本内核打通。

## 5. 优先级逻辑

- **P0（高）**：审批流治理、技能版本治理、编排管控台——三者共享"版本 + 审计 + 策略"内核，命中空白最确定（confirm 0、registry 0、编排×统计/成本主榜 0），且已有场景化落地证明需求真实（publish-gate +71.9%、diff-approval 2,592、skills-manager 37,213）。
- **P1（中高）**：工作区检查点/回滚、团队任务台账——需求装机明确（task-ledger 4,965、agent-teams 14,493、workspace×git 7.29%），但需要与 P0 的审计/审批内核联动才有企业价值。
