## 1. 执行摘要：当前生态是「个人玩具」供给，企业四根支柱近乎空白

把任务一识别的「高确定性需求」放到企业放大镜下有残酷反差：**装机底座巨大（`deepseek-ai/deepseek-harness` 周下载 1,208,788），但围绕它的企业协作层几乎是真空**。我分工的四个主题汇聚成一条清晰判断：

| 企业支柱 | 生态现状（数字） | 结论 |
|---|---|---|
| **团队协同** | 通知/提醒 872 仓周下载合计仅 **87,949**（占全库 1.12%），生产力/办公 805 仓 **scoreMax 仅 89.1、`score≥90` = 0 仓**，通知∩自动化 = **5 仓且这 5 仓周下载全为 null、score 最高仅 54.6** | 只有「个人看板小工具」，没有团队级协同 |
| **流程触达** | 通知 872 仓中 55 个是「声音/铃声」、27 个 IM 转发、13 个邮件转发，真正的「事件/事件通知」类仅 **3 仓**；`dsh-event-notice` 却 **+489.4%** | 需求真实存在且爆发，但被当成「响铃」做浅了 |
| **品牌一致** | 设计/排版 3,937 仓增长中位 **-1.4%**，头部皮肤 `pc2005-cloud/dsh-pet` 周下载 95,892 但 **-33.4%**、`dsh-skins` -25.7%、`dsh-deep-whale` -23.2%；设计列平均 lift/有效供给比 **0.469（全域最薄，见任务一 §4）**；会话管理×设计矩阵格 = **343 但头部全是界面微调/皮肤** | 「换皮」红利退潮，设计系统供给缺位 |
| **合规本地化** | 中文本地化 744 仓（**占全库 1.9%**）、**主榜 0 仓**、star 中位 0、409 仓零 star，**中文×安全仅 26 仓**、中文×框架 23 仓；182/744 仓只是「中文文案」、仅 1 仓涉及字体 | 停留在「翻译界面」，无术语库/合规审校/i18n 工程 |

**总判断：企业不为「又一个插件」买单，而为「可治理、可触达、可一致、可合规的协作底座」买单。** 机会不在再造智能体框架（智能体 6,389 仓已红海），而在把这些散点工具升维成企业级能力层。

## 2. 分主题深挖：空白在哪里

### 2.1 任务 / 日程 / 看板协同 —— 有工具无「团队」，有看板无「流程」

**供给现状（仓库名关键词统计）**：`task` 281 仓（周下载 34,867）、`board` 276 仓（33,688）、`todo` 93 仓（15,949）、`calendar` 35 仓（6,566）、`schedule` 55 仓（3,467）、`kanban` 36 仓（7,202）、`planner` 21 仓（1,532），**`agenda` 0 仓**、中文 `协作`/`团队` 关键词 **0 仓**（仓库名维度）。`team` 162 仓（周下载 66,653）绝大多数是 `dsh-agent-teams`/`suifei/dsh-ai-team` 这类「多智能体编排」，不是「多人协作」。

**头部全是单机小工具，无企业级爆款**：

- `cq-guojia/dsh-task-ledger`：生产力榜首 **score 89.1 / ★15 / 周下载 4,965**（个人记账式任务台账，star 极低）；
- `cloader/dsh-taskboard`：score 78.2 / ★84 / 周下载 1,972 / **增长 -20.7%**；
- `kira905/dsh-task-board-local`：score 77.2 / ★2 / 周下载 788（名字即「local」）；
- `topmindspace/dsh-super-kanban`：score 96.7 / ★107 / 周下载 2,311 / +82.3%，已是该细分最亮眼者，但仍是单人超级看板；
- `loyalchiiina/dsh-schedule-calendar`：周下载 1,280 / +142.9%，日程类也仅此量级。

**核心空白**：生产力 805 仓 **`score≥90` = 0**（任务一 §1 即以「生产力 scoreMax 仅 89.1、无爆款」列为缺口）；通知∩生产力仅 **57 仓、周下载合计 3,683**，意味着「任务状态变更 → 团队触达」几乎无人打通。缺的是「团队共享看板 + 任务绑定会话/工作区 + 成员分工与进度汇总 + 与企业 IM/日历双向同步」，而非又一个本地 todo。

### 2.2 事件通知与消息聚合 —— 「响铃」过剩，「事件总线」缺位

**通知盘子的真实形态（872 仓拆解）**：

- 声音/铃声类 55–57 仓（**6.5%**）：`billcx330/dsh-plugin-notify-sounds`、`machine-126/dsh-alert-sound`、`gexiubinhelloworld/dsh-qq-sounds` 等；
- IM 转发 27 仓（3.1%）：`wssfk12138/dsh-wechat-notify`、`sflaer/dsh-telegram-relay`、`ljnljn2005/dsh-wecom-notify`；
- 邮件 13 仓（1.5%）：`stardustlc666/dsh-email`；桌面 29 仓（3.3%）；
- **真正的「事件」类仅 3 仓（0.3%）**——通知被行业默认理解成「任务完成响一声」，不是「工作流事件」。

**需求信号强但供给极浅**：`sorchk/dsh-event-notice` **+489.4%（周下载 1,774）**、`loyalchiiina/dsh-schedule-calendar` +142.9%、`aicivilization/dsh-mishu` +289.8%（IM 秘书）——爆发式增长证明「会话/任务完成→触达」是真痛点。但：

- 通知∩自动化 = **5 仓**：`joblessjoe/dsh-ping-me`、`yashua233/dsh-mail-command`、`wodongx123/dsh-qq-notify`、`jensentsts/dsh-completion-sound`、`ljnljn2005/dsh-wecom-notify`——**全部 `weekly=null`、star ≤1、score 最高 54.6**，即「通知自动化」在生态里等于零；
- 通知∩工作流 = 121 仓，但头部仍是声音类（周下载合计仅 8,658）；通知∩安装管理 = 49 仓（多为 `dsh-update-checker` 更新提醒）；
- 通知族 **star 中位 0、526/872 仓零 star、主榜 0 仓、周下载合计仅 87,949**——低质长尾。

**企业缺口**：缺「统一事件模型（会话结束 / 任务完成 / 额度耗尽 / 构建失败）→ 多通道路由（飞书/企微/钉钉/邮件/桌面）→ 聚合去重 / 免打扰时段 / 值班升级 → 送达审计留痕」。现有方案是碎片化铃音和单向转发，无路由、无去重、无审计，无法满足合规「通知可追溯」。

### 2.3 团队知识沉淀 —— 个人记忆很强，组织记忆很弱

**交集数据揭示断层**：文档/笔记 2,706 仓、知识库/RAG 507 仓、搜索 2,177 仓看似充足，但与「会话/工作区」结合极少：

- 文档×会话 493 仓（周下载 105,613），头部 `omdsh-dev/dsh-mnemon` 是**个人记忆**检索、`ggboya/dsh-paper-reader` 是个人论文阅读；
- **RAG×会话仅 77 仓**（周下载 23,045）、文档×工作区 350 仓、RAG×文档 140 仓、RAG×搜索 168 仓；
- 旗舰 `zilliztech/memsearch` score 99.1、周下载 13,548、+123.5%，但本质是「个人长期记忆 + 语义检索」；`tencent/weknora` ★37,492 但 -15%。

**企业缺口**：缺「团队级知识空间（成员/权限/空间隔离）+ 会话产物自动沉淀（结论/决策/代码 diff→知识条目）+ 引用溯源与版本 + 与文档/IM 双向同步 + 离职交接」。现有替代都是「个人第二大脑」，无组织维度、无 ACL、无审计——这与「中文×安全仅 26 仓」叠加，说明**合规知识治理几乎为零**。

### 2.4 中文本地化 / i18n —— 翻译文案多，工程化与合规少

**结构（744 仓）**：增长中位 **-1.5%**、star 中位 0、**409 仓零 star**、周下载合计 86,605、**主榜 0 仓**（任务一 §1 已独立列为缺口）。形态拆解：

- `zh|cn|chinese|中文` 182 仓（24.5%）——绝大多数是「把界面文案翻成中文」；
- `translate|翻译` 36 仓（如 `epcn-fla/dsh-prompt-translation` +66.6%、`unclek/dsh-think-translate` score 91 / ★84）；
- `lang|language|语言` 16 仓、`prompt` 7 仓、`docx|pdf|文档` 13 仓，**`font|字体` 仅 1 仓**。

**交叉空白**：中文×安全 **26 仓**（最高 `pensivefei/dsh-secure-audit` score 85.8）、中文×框架 23 仓（最高 `imlishiyuan/deepseek-harness-zh-cn` score 80）、中文×设计 117 仓（多为 `dsh-bloom-theme` 之类主题皮肤）、中文×技能 104 仓。

**企业缺口**：缺「术语库/品牌词表统一管理、双语对照与人工审校工作流、合规文案（隐私政策/免责声明/行业术语）、语言包热切换与占位符/复数/编码正确性、中文排版（标点/断行/字体回退）、译文质量评测」。现有是散装语言包，无术语一致性、无合规审查、无 i18n 工程化。

### 2.5 设计系统与排版规范 —— 皮肤退潮，规范要求浮出水面

**供给与动能**：设计/排版 3,937 仓，增长中位 **-1.4%**，负增长仓 328 vs 正增长 172。头部清一色皮肤/宠物且大幅下滑：

| 仓库 | 周下载 | 增长 | 类型 |
|---|---|---|---|
| `pc2005-cloud/dsh-pet` | 95,892 | **-33.4%** | 桌面宠物皮肤 |
| `zhu1090093659/dsh-skins` | 22,105 | -25.7% | 皮肤 |
| `small-tailqwq/dsh-deep-whale` | 12,767 | -23.2% | 人格皮肤 |
| `webkubor/dsh-bloom-theme` | 2,423 | -45.1% | 主题（且属中文×设计） |
| `nonamelego/dsh-catppuccin-theme` | 2,022 | -33.5% | 主题 |

**「表层化」实证**：矩阵中会话管理×设计 = **343 仓**（智能体×设计 = 180，工作区×设计 = 157），但我对全量交集按周下载排序，头部是 `wlj521/dsh-ui-tweaks`、`zuojinxin/dsh-sidebar-manager`、`ferrisching/dsh-prompt-predict`、`taoser258/dsh-client-ui-skin-qingxiao`、`xbzbing/dsh-openviking-manager`——**全是界面微调、侧边栏、皮肤、提示词预测**，没有一个是 Design Token、组件规范、品牌主题包或一致性检查器。任务一 §4 测得「设计列平均 ratio 0.469（全域最薄）」，与这里的数据完全吻合：**设计是「需求广、有效供给薄」的最典型空白列**。

**企业缺口**：缺「Design Token / 组件规范 / 多品牌白标主题包 / 输出排版引擎（汇报、PPT、文档）/ 无障碍与一致性检查 / 设计资产版本管理」。少数正向信号说明方向对：`op7418/dsh-guizang-design` score 96.7、周下载 9,039、**+25.8%**（排版模板），`alibaba-damo-academy/yugoo-design` score 90.5——但都是孤岛，未成体系。

## 3. 优先级判断（企业价值 × 空白确定性 × 数据信号）

- **高**：需求信号强（高增长/高下载）且空白确定性高（交集=5、scoreMax 89.1、主榜 0）。→ 事件通知中枢、团队协同看板、团队知识治理。
- **中高**：空白确定但需求需引导（企业合规/品牌意识尚在觉醒）。→ i18n 工程链、Design Token/品牌规范引擎。
- **中**：补齐型、可与上述捆绑交付。→ 合规审计留痕、企业内部插件目录治理。

## 4. 可执行开发建议（做什么 / 解决什么 / 目标用户 / 证据 / 优先级）

1. **NotifyHub 企业事件通知中枢**（标签 42+23+29+41+16）——把「响铃」升级为事件总线：统一事件模型 + 多通道路由（飞书/企微/钉钉/邮件/桌面）+ 聚合去重/免打扰/值班升级 + 送达审计。**证据**：通知周下载仅 87,949、通知∩自动化=5（全 null 下载）、`dsh-event-notice` +489.4%。**目标用户**：中台/运维/跨时区团队。**优先级：高**（难度中）。

2. **TeamFlow 团队协同看板桥**（标签 43+21+22+29）——团队共享看板，任务↔会话↔工作区↔成本四向绑定，进度汇总。`cloader/dsh-taskboard` -20.7%、生产力 `score≥90`=0、通知∩生产力仅 57 仓 wk 3,683。**目标用户**：研发/项目团队。**优先级：高**（难度中高）。

3. **TeamKnowledge 团队知识沉淀与治理**（标签 8+10+21+22+39）——会话产物自动沉淀为团队知识条目 + ACL 空间隔离 + 引用溯源 + 离职交接。**证据**：RAG×会话仅 77 仓、中文×安全仅 26、memsearch 个人记忆独占 13,548 周下载。**目标用户**：知识密集型团队、合规行业。**优先级：高**（难度高）。

4. **i18nOps 本地化工程工具链**（标签 38+30+45+39）——术语库/品牌词表 + 审校工作流 + 合规文案 + 占位符/复数/编码校验 + 中文排版 + 译文评测。**证据**：744 仓主榜 0、182 仓仅中文文案、字体仅 1 仓、中文×安全 26。**目标用户**：出海/多语言/受监管企业。**优先级：中高**（难度中）。

5. **BrandKit 设计 Token 与排版规范引擎**（标签 37+21+43）——Design Token / 组件规范 / 多品牌白标 / 输出排版（PPT/报告）/ 一致性检查。**证据**：设计列供给比 0.469 全域最薄、皮肤头部 -33.4%、会话×设计=343 但表层化、`dsh-guizang-design` +25.8%。**目标用户**：品牌/市场/设计团队。**优先级：中高**（难度中高）。

6. **ComplyLog 合规留痕包**（标签 42+39+38+10）——把通知送达、任务变更、知识访问统一审计留痕并支持导出，满足等保/行业审计。**证据**：中文×安全 26、通知∩安全极低、通知零审计能力。**目标用户**：金融/医疗/政企。**优先级：中**（难度中）。

7. **InternalCatalog 企业插件目录治理**（标签 48+41+39）——企业内部插件的准入审核、白名单、版本与权限治理。**证据**：插件合集 1,081 仓 ★P90=1、823 仓零 star、主榜仅 1 仓，是可信目录的空白。**目标用户**：企业 IT/平台团队。**优先级：中**（难度低）。
